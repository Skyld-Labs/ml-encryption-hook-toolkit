# PyTorch Hook

Implementation of the ML encryption hook for PyTorch/TorchScript models.

## Overview

This directory contains the PyTorch (LibTorch)-specific implementation of the encryption hook mechanism, based on the TensorRT reference implementation. Unlike the other frameworks in this toolkit, PyTorch's C++ API is tightly bound to its runtime — there is no separate deserialization or graph compilation phase. The model is loaded and immediately executed via the same `torch::jit::load()` call. This means the hook must intercept at the point where the decrypted bytes are handed to the loader, before any execution begins.

The victim program (`infer_pt`) decrypts an encrypted TorchScript model in memory and loads it via `torch::jit::load(std::istream&)`, which is the attack surface: a plain exported C++ function with a mangled symbol that we can intercept via symbol interposition in a shared library.

```
pytorch/

│   ├── Makefile

│   ├── pt_load_hook.cpp             # LD_PRELOAD hook — intercepts torch::jit::load(istream&)
│   └── .gitkeep

│   ├── compile_pt

│   └── .gitkeep
└── models/                           # All model files, at every stage (kept in git via .gitkeep)
    ├── .gitkeep

```

`src/` holds only code, `build/` holds only compiled binaries (git-ignored), and `models/` holds every model artifact — original, encrypted, or stolen — regardless of which stage produced it. `models/.gitkeep` keeps the empty folder tracked in git even before any artifact has been generated.

## Requirements

- Linux x86_64 (tested on Ubuntu 24.04)
- `g++` with C++17 support, and `make`
- LibTorch (PyTorch C++ API) — pre-built CPU-only distribution
- OpenSSL development headers (`libssl-dev`)

Run the install script from the `pytorch/` directory to install everything above in one go:

```bash
./install_requirements.sh
```

This downloads and installs LibTorch 2.5.1 (CPU-only) into `~/Documents/Skyld/libtorch`, then verifies `g++` supports C++17 and installs `libssl-dev` if needed.

If LibTorch is installed elsewhere, adjust `LIBTORCH_ROOT` at the top of `src/Makefile` — everything else derives from that one variable. Note: you can override it at runtime with `make LIBTORCH_ROOT=/path/to/libtorch`.

## Build & run (via Makefile)

All commands below are run from `pytorch/src`. The `Makefile` wraps every build and run step, including setting the necessary paths. Compiled binaries are placed in `../build`, which is git-ignored — nothing under `build/` should be committed.

```bash
make all                # compiles compile_pt, infer_pt, and pt_load_hook.so into ../build
make run-baseline       # encrypts ../models/model.pt, runs the victim normally (no attack)
make run-attack         # encrypts the model, attacks the victim, dumps the stolen model to ../models/
make clean              # removes ../build entirely and cleans up temporary model files
```

Override the password or the input model without editing the `Makefile`:

```bash
make run-attack PASSWORD=yourpassword MODEL=../models/other_model.pt
```

### What each target does

- **`compile_pt`**: reads `model.pt`, encrypts it with AES-256-ECB using the password as the key derivation source (SHA-256), and writes it to `../models/model.pt.enc`.
- **`infer_pt`**: reads `model.pt.enc`, decrypts it in RAM using the provided password, wraps the decrypted bytes in an `std::istringstream`, and calls `torch::jit::load(stream)` to load and verify the model — this is the legitimate, non-hooked path.
- **`pt_load_hook.so`**: the `LD_PRELOAD` library used in `make run-attack`. It intercepts `torch::jit::load(std::istream&, std::optional<c10::Device>, bool)` via symbol interposition (exact mangled name collision). It reads the entire decrypted buffer from the stream, dumps it to `../models/dumped_model.pt`, rewinds the stream, and passes control to the real `torch::jit::load`. The victim process continues without any visible sign of compromise.

## Troubleshooting / Quirks

- Verify that `LIBTORCH_ROOT` in `src/Makefile` points to a valid LibTorch installation.
- The hook relies on a specific `torch::jit::load` overload; alternative loading paths may require additional inspection.
- If the victim binary fails, ensure the decrypted model stream is rewound correctly by the hook.

## How the hook works

Unlike frameworks that dispatch through vtables or C API function-pointer tables, PyTorch's `torch::jit::load(istream&)` is a plain exported C++ function. The attack uses **symbol interposition**:

1. The hook defines its own `torch::jit::load(std::istream&, std::optional<c10::Device>, bool)` in the exact same namespace and with the exact same signature.
2. The compiler mangles both to the **same symbol name**: `_ZN5torch3jit4loadERSiSt8optionalIN3c106DeviceEEb`
3. When the shared library is `LD_PRELOAD`'d, the dynamic linker resolves calls to that symbol to the hook's definition first.
4. The hook then calls `dlsym(RTLD_NEXT, ...)` to resolve the real function, capture the plaintext model, and forward the call to the original.

This technique was already demonstrated successfully with TensorRT's `deserializeCudaEngine`, but PyTorch's public API design makes it even simpler: no vtable patching, no table lookup — just one function with one mangled name.

## Manual build (if you're not using `make`)

```bash
cd src

# Encrypt a model
g++ -std=c++17 compile_pt.cpp -o ../build/compile_pt -lcrypto
../build/compile_pt changeme ../models/model.pt ../models/model.pt.enc

# Compile the victim
g++ -std=c++17 \
  -I~/Documents/Skyld/libtorch/include \
  -I~/Documents/Skyld/libtorch/include/torch/csrc/api/include \
  infer_pt.cpp -o ../build/infer_pt \
  -L~/Documents/Skyld/libtorch/lib \
  -Wl,-rpath,~/Documents/Skyld/libtorch/lib \
  -ltorch -ltorch_cpu -lc10 -lcrypto

# Compile the hook
g++ -std=c++17 -fPIC -shared \
  -I~/Documents/Skyld/libtorch/include \
  -I~/Documents/Skyld/libtorch/include/torch/csrc/api/include \
  pt_load_hook.cpp -o ../build/pt_load_hook.so \
  -L~/Documents/Skyld/libtorch/lib \
  -Wl,-rpath,~/Documents/Skyld/libtorch/lib \
  -ltorch -ltorch_cpu -lc10 -ldl

# Run the attack
cd ../build
LD_LIBRARY_PATH=~/Documents/Skyld/libtorch/lib LD_PRELOAD=./pt_load_hook.so ./infer_pt ../models/model.pt.enc changeme
```

## Security implications

- **Plain C++ function, plain interposition**: There is no indirection here — the function is directly exported and directly callable. Symbol interposition is the only technique needed.
- **Same hook, any wrapper**: Whether the application loads models via `torch::jit::load`, `torch::jit::LiteModuleLoader`, or any other entry point, if they internally call `torch::jit::load(istream&)`, the same hook applies.
- **Runtime extraction unchanged**: The underlying principle remains consistent across all four frameworks in this toolkit: once the decrypted model is available in memory for execution, it is observable by any hook with the correct technique.
