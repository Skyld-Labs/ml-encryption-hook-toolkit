# OpenVINO Hook

Implementation of the ML encryption hook for OpenVINO models.

## Overview

This directory contains the OpenVINO-specific implementation of the encryption hook mechanism, based on the TensorRT reference implementation.

Unlike TensorRT (which loads a prebuilt engine directly) and ONNX Runtime / TFLite (which load their native file format directly), OpenVINO requires converting the input `.onnx` model into its own intermediate representation (IR) first: an XML file describing the graph, plus a binary file holding the weights. Both are packed into a single buffer before encryption so the toolkit only has to handle one encrypted artifact per model, consistent with the other frameworks.

## Structure

```
openvino/
├── README.md                      # This file
├── install_requirements.sh        # Installs OpenVINO Runtime + OpenSSL dev headers
├── src/                            # All source code and the build system
│   ├── Makefile
│   ├── test_load.cpp                     # Sanity check: loads an ONNX model with OpenVINO, prints IO info
│   ├── compile_ov.cpp                    # Converts ONNX to OpenVINO IR (XML+weights), then encrypts it (AES-256-ECB)
│   ├── infer_ov.cpp                      # Loads the encrypted IR, decrypts it in memory, runs inference
│   └── openvino_read_model_hook.cpp      # LD_PRELOAD hook that dumps the decrypted IR before OpenVINO uses it
├── build/                          # Compiled binaries (generated, not tracked by git)
│   ├── test_load
│   ├── compile_ov
│   ├── infer_ov
│   └── openvino_read_model_hook.so
└── models/                         # All model files, at every stage (kept in git via .gitkeep)
    ├── .gitkeep
    ├── model.onnx                        # Input model (source)
    ├── model.ov.enc                      # Encrypted IR (generated)
    ├── dumped_model.xml                  # Stolen IR graph (generated by the attack)
    └── dumped_weights.bin                # Stolen weights (generated by the attack)
```

`src/` holds only code, `build/` holds only compiled binaries (git-ignored), and `models/` holds every model artifact — original, encrypted, or stolen — regardless of which stage produced it. `models/.gitkeep` keeps the empty folder tracked in git even before any artifact has been generated.

## Requirements

- Linux x86_64 (tested on Ubuntu 24.04)
- `g++` with C++17 support, and `make`
- OpenVINO Runtime 2024.6.0 with C++ headers
- OpenSSL development headers (`libssl-dev`)

Run the install script from the `openvino/` directory to install everything above in one go:

```bash
./install_requirements.sh
```

This downloads and installs OpenVINO Runtime 2024.6.0 into `/opt/intel/openvino_2024.6.0` (the official APT repo has known dependency issues on Ubuntu 24.04 with `libtbb2`, so the official archive is used instead), then installs `libssl-dev`.

If OpenVINO is installed elsewhere, adjust `OV_ROOT` at the top of `src/Makefile` — everything else derives from that one variable.

## Build & run (via Makefile)

All commands below are run from `openvino/src`. The `Makefile` wraps every build and run step, including setting `LD_LIBRARY_PATH` for OpenVINO's dependencies (notably TBB), so no manual `export` is needed. Compiled binaries are placed in `../build`, which is git-ignored — nothing under `build/` should be committed.

```bash
make all           # compiles test_load, compile_ov, infer_ov, and the hook into ../build
make run-baseline  # encrypts ../models/model.onnx, runs inference normally (no attack)
make run-attack    # encrypts the model, runs the attack, dumps the stolen IR to ../models/
make clean         # removes ../build entirely
```

Override the password or the input model without editing the `Makefile`:
```bash
make run-attack PASSWORD=yourpassword MODEL=../models/other_model.onnx
```

### What each target does

- **`compile_ov`**: converts `model.onnx` to OpenVINO IR, packs the XML and weights into one buffer (`[4-byte XML length][XML][weights]`), encrypts it with AES-256-ECB, and writes it to `../models/model.ov.enc`.
- **`infer_ov`**: reads `model.ov.enc`, decrypts it in RAM, splits it back into XML and weights, and calls `core.read_model(xmlStr, weightsTensor)` to run inference — this is the legitimate, non-hooked path.
- **`openvino_read_model_hook.so`**: the `LD_PRELOAD` library used in `make run-attack`. It intercepts `read_model` and dumps its arguments to `../models/dumped_model.xml` and `../models/dumped_weights.bin` before letting the real function proceed.

### Automatic symbol resolution

Building the hook requires binding to the exact mangled symbol name of `ov::Core::read_model(const std::string&, const ov::Tensor&) const`, which is version-specific. Rather than hardcoding it, `src/Makefile` resolves it automatically at parse time:

```make
OV_READ_MODEL_SYMBOL := $(shell nm -D $(OV_LIBPATH) 2>/dev/null | grep 'read_modelERKNSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEEERKNS_6TensorE' | awk '{print $$3}')
```

The `check-symbol` target fails the build early with a clear error if the symbol can't be found (e.g. `OV_ROOT` is wrong, or the OpenVINO ABI changed in a newer version), instead of failing later with a confusing linker error.


### Manual build (if you're not using `make`)

```bash
export LD_LIBRARY_PATH=/opt/intel/openvino_2024.6.0/runtime/lib/intel64:/opt/intel/openvino_2024.6.0/runtime/3rdparty/tbb/lib:$LD_LIBRARY_PATH

mkdir -p ../build

g++ -std=c++17 compile_ov.cpp -o ../build/compile_ov \
    -I/opt/intel/openvino_2024.6.0/runtime/include \
    -L/opt/intel/openvino_2024.6.0/runtime/lib/intel64 \
    -L/opt/intel/openvino_2024.6.0/runtime/3rdparty/tbb/lib \
    -Wl,-rpath,/opt/intel/openvino_2024.6.0/runtime/lib/intel64 \
    -Wl,-rpath,/opt/intel/openvino_2024.6.0/runtime/3rdparty/tbb/lib \
    -lopenvino -ltbb -ltbbmalloc -lcrypto

# infer_ov and openvino_read_model_hook.so follow the same flag pattern —
# see src/Makefile for the exact commands.
```

## Run manually, step by step

```bash
cd src
make all

../build/compile_ov ../models/model.onnx model.ov.enc <password>
../build/infer_ov ../models/model.ov.enc <password>
LD_PRELOAD=../build/openvino_read_model_hook.so ../build/infer_ov ../models/model.ov.enc <password>
```

The decrypted IR is dumped to `../models/dumped_model.xml` and `../models/dumped_weights.bin`, identical to the in-memory decrypted buffers — despite the on-disk file being encrypted. Verify with:
```bash
diff ../models/dumped_model.xml <(head -c <xml_length> ...)   # or compare sizes reported by infer_ov
```
(the sizes printed by `infer_ov` and by the hook should match exactly).

## How it works

1. `infer_ov` reads the encrypted `.ov.enc` file and decrypts it in RAM (AES-256-ECB, key derived from the password via SHA-256), then splits it back into the IR XML string and the weights buffer.
2. It calls `core.read_model(xmlStr, weightsTensor)` to load the decrypted IR into OpenVINO.
3. `ov::Core::read_model(const std::string&, const ov::Tensor&) const` is the hook target. Unlike the TensorRT hook (which patches a C++ vtable pointer at runtime), this hook intercepts the exported symbol directly: it resolves the exact mangled symbol name and binds `hook_read_model` to it via `__asm__(...)`, then forwards to the real implementation via `dlsym(RTLD_NEXT, ...)`, since the OpenVINO ABI is stable enough to link against directly through `LD_PRELOAD`.
4. When `infer_ov` calls `read_model`, the hook's function runs first: it dumps the XML and weights buffers to disk, then forwards the call to the real `read_model` so the program behaves normally and the victim notices nothing.

The exact mangled symbol name is version-specific; `src/Makefile` re-resolves it automatically on every build (see "Automatic symbol resolution" above), so upgrading OpenVINO doesn't require touching the source. To check it manually:
```bash
nm -D /opt/intel/openvino_2024.6.0/runtime/lib/intel64/libopenvino.so | grep read_model
```
